# FM-01: Show the trove owner and offer management only to the owner

**Sensitive: yes.** Describe this change as hardening wherever it is visible: code
comments, test names, commit messages and the pull request. Say what the page now does.
See AGENTS.md, worker rule 7.

## Objective

`/borrow/manage/[id]` renders a position from the id in the URL
(`apps/app.mento.org/app/borrow/manage/[id]/page.tsx:12-23`). `ManageTroveView`
validates only the `?token=` parameter (`manage-trove-view.tsx:146-157`). It renders the
Adjust, Interest Rate and Close tabs whenever trove data loads
(`manage-trove-view.tsx:378-431`). The page never reads who owns the trove, and never
shows it.

Make the page owner-aware:

- Read the owner on-chain with `TroveNFT.ownerOf(troveId)`, and show it under the
  trove id.
- Render the three management tabs only when the connected wallet is the owner and the
  trove status is `active` or `zombie`.
- Show everyone else the same stats, read-only, with one short notice.
- Make the adjust transaction builder refuse to build for a non-owner, so the rule
  doesn't rest on the UI alone.

Not in scope, and unchanged:

- `adjust-form.tsx`, `rate-form.tsx` and `close-form.tsx`, which simply aren't rendered
  for non-owners;
- the open-trove flow, the dashboard and the activity panel.

## Hard rules for this task

- **The owner comes from chain state.** Use `ownerOf` only, never the subgraph or the
  URL.
- **Fail closed.** Render no management tab while the owner is loading, if the lookup
  fails, or if the status is not `active`/`zombie`. `ownerOf` reverts for an id with no
  NFT (a closed or never-opened trove); treat that as "no owner".
- **Compare addresses case-insensitively.**
- **Do not change what any form signs.** This task gates rendering and adds one
  ownership check before the adjust flow starts. Nothing else.
- **Tests run in different environments.** `@repo/web3` tests run in node with no DOM:
  test the exported pure helpers, not the hook. App tests run in jsdom.

## Work

1. **`use-trove-owner.ts` (new).**
   - `fetchTroveOwner(publicClient: PublicClient, chainId: number, symbol: string,
troveId: bigint): Promise<Address>`. Resolve `troveNFT` with `getBorrowRegistry` and
     `resolveAddressesFromRegistry` exactly as `use-user-troves.ts:36-43` does. Then
     `readContract` with `TROVE_NFT_ABI`, `functionName: "ownerOf"`, `args: [troveId]`.
   - `isTroveOwner(owner?: string, account?: string): boolean`. True only when both are
     set and equal ignoring case.
   - `useTroveOwner(troveId: string | undefined, symbol = "GBPm")`:
     - `useQuery<Address>`;
     - key `["borrow", "troveOwner", symbol, chainId, troveId]`;
     - `enabled: !!publicClient && !!troveId`, `retry: false`, `refetchInterval: 15_000`.
   - Export all three from `hooks/index.ts`, next to `useTroveData`.
2. **`use-trove-owner.test.ts` (new).** `vi.mock` the two registry functions and use a
   stub client. Assert that:
   - `fetchTroveOwner` returns the `ownerOf` result, reading from the resolved TroveNFT
     address with the right args;
   - `isTroveOwner` is case-insensitive and false when either side is missing.
3. **`use-adjust-trove.ts`.** At the top of `mutationFn`, after the `sdk` check:
   - resolve `chainId = getChainId(wagmiConfig)` and
     `publicClient = getPublicClient(wagmiConfig, { chainId })` (both from `wagmi/actions`);
   - call `fetchTroveOwner(publicClient, chainId, symbol, BigInt(params.troveId))`;
   - if `!isTroveOwner(owner, account)`, call
     `toast.error("Only the owner of this position can adjust it.")` and throw an `Error`
     with the same text, before `executeFlow`.
4. **`manage-trove-view.tsx`.**
   - **New hooks.** Call `useAccount()` from `@repo/web3/wagmi`, and
     `useTroveOwner(isValidToken ? troveId : undefined, debtToken.symbol)` next to
     `useTroveData`, keeping the hook order unconditional.
   - **Owner line.** Under the trove-id row (291-311), add `Owner` plus the owner rendered
     as `shortenAddress(owner, false)`. Link it to
     `${getExplorerUrl(chainId)}/address/${owner}` with `target="_blank"` and
     `rel="noopener noreferrer"`. Show a small `Skeleton` while loading and `Unknown` if the
     lookup failed.
   - **Tabs card.** Replace the tabs card (378-431) with the first matching case below.
     Each notice uses the existing `Card`/`CardContent` style.
     - (a) Owner loading: `<Skeleton className="h-64 w-full rounded-lg" />`.
     - (b) Status not `active`/`zombie`: "This position is closed and can no longer be
       managed."
     - (c) Owner lookup failed: "The owner of this position couldn't be confirmed, so
       management is unavailable. Please try again later."
     - (d) Wallet not connected: "Connect the owner's wallet to manage this position."
     - (e) Connected wallet is not the owner: "This position belongs to {owner link}. Only
       the owner's wallet can manage it."
     - (f) Otherwise: the existing tabs, unchanged.
5. **`manage-trove-view.test.tsx`.**
   - **Mocks.** Extend the `@repo/web3` mock with `useTroveOwner`, `isTroveOwner` (a
     case-insensitive compare), `shortenAddress` and `getExplorerUrl`. Extend the
     `@repo/web3/wagmi` mock with `useAccount`.
   - **Tests.** One test per case (a)–(f). Assert which of the `adjust-form`, `rate-form`
     and `close-form` test ids render. Add one more test where the owner and the account
