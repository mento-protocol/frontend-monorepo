## Objective

The Bridge tab embeds Wormhole Connect (`bridge-view.tsx:151-157`) with `bridgeConfig`
(`bridge-config.ts:181`). The widget connects its own source and destination wallets and
signs the transfer itself. It renders even when no wallet is connected in the app
(`bridge-view.tsx:104-111`). The app's wallet screening runs on the wallet connected in
the app header (`app/hooks/use-sanctions-check.ts:14,27-47` inside `SanctionsGuard`).

Wormhole Connect 6.0.0 provides a pre-transfer hook for this. It calls
`validateTransferHandler(details)` with `fromWalletAddress` and `toWalletAddress` when the
user confirms a transfer, and aborts the transfer on `{ isValid: false }`.

This task makes two changes:

- screen both wallets of every transfer through the existing `/api/sanctions` endpoint;
- show the widget only once a wallet is connected in the app.

It does not change the sanctions route, the app-wide guard, the bridge routes or tokens,
or the widget theme.

## Hard rules for this task

- **Fail closed.** A wallet is cleared only by a `2xx` response whose JSON body has
  `isSanctioned === false`. Anything else blocks the transfer:
  - a non-2xx status;
  - a network error or thrown fetch;
  - invalid JSON;
  - `isSanctioned` that is `true`, `null` or missing;
  - an empty address.
- **Allow a `degraded: true` pass.** The route's `SANCTIONS_CHECK_FAIL_OPEN` switch
  (`app/api/sanctions/config.ts`) stays the single policy knob, exactly as for the
  app-wide guard.
- **Don't change the route, the hook or the guard.** They are not yours.
- **Use exactly these user-facing messages**, which Wormhole shows inside the widget:
  - `BLOCKED`: "This transfer can't be completed because one of the wallets isn't
    eligible to use Mento. If you believe this is an error, please contact support."
  - `UNVERIFIED`: "We couldn't verify the wallets for this transfer. Please try again
    later."
- **Keep the Wormhole runtime out of the view test.** Importing `bridge-config.ts` pulls
  in the whole Wormhole runtime, so `vi.mock("./bridge-config")` in the view test.
  `transfer-screening.ts` may only `import type` from Wormhole.

## Work

1. **`transfer-screening.ts` (new).**
   - `screenAddress(address: string, fetchImpl: typeof fetch = fetch): Promise<"cleared" | "blocked" | "unverified">`.
     Fetch `` `/api/sanctions?address=${encodeURIComponent(address)}` ``, following the
     rules above. `"blocked"` means `isSanctioned === true`.
   - `createBridgeTransferValidator(fetchImpl = fetch)`, typed as
     `NonNullable<config.WormholeConnectConfig["validateTransferHandler"]>`. It:
     - dedupes `fromWalletAddress` and `toWalletAddress` case-insensitively;
     - screens them in parallel;
     - returns `{ isValid: false, error: BLOCKED }` if any is blocked, otherwise
       `{ isValid: false, error: UNVERIFIED }` if any is unverified, otherwise
       `{ isValid: true }`.
   - `export const validateBridgeTransfer = createBridgeTransferValidator();`
2. **`bridge-config.ts`.** Import `validateBridgeTransfer`, and add the line
   `validateTransferHandler: validateBridgeTransfer,` to `bridgeConfig`, right after
   `network: "Mainnet",`.
3. **`bridge-view.tsx`.**
   - Read `isConnected` from `useAccount()` (`@repo/web3/wagmi`).
   - Render order:
     1. `!isBridgeSupportedChain` → the existing `BridgeTestnetState`;
     2. `!isConnected` → a new `BridgeConnectState`;
     3. otherwise the widget.
   - `BridgeConnectState` copies `BridgeTestnetState`'s layout and has:
     - heading "Connect your wallet to bridge";
     - text "Connect your wallet to bridge Mento stablecoins between Celo, Monad and
       Polygon.";
     - `<ConnectButton size="lg" text="Connect Wallet" />`.
   - The effect at 117-136 attaches the accessibility patch. Add `!isConnected` to its
     early return and `isConnected` to its dependencies. Otherwise the patch never
     attaches when the widget mounts after the user connects.
4. **`transfer-screening.test.ts` (new).** Use a fake `fetch`, one test each:
   - both cleared → valid;
   - source blocked → `BLOCKED`;
   - destination blocked → `BLOCKED`;
   - `502` → `UNVERIFIED`;
   - `429` → `UNVERIFIED`;
   - fetch throws → `UNVERIFIED`;
   - invalid JSON → `UNVERIFIED`;
   - `isSanctioned: null` → `UNVERIFIED`;
   - degraded pass → valid;
   - same address in different case → exactly one fetch;
   - empty destination → invalid with no fetch;
   - the address is URL-encoded.
5. **`bridge-view.test.tsx` (new).**
   - Mocks:
     - `next/dynamic`: a stub widget with `data-testid="bridge-widget"`;
     - `./bridge-config`, `next-themes` and `next/image`;

       and a `ConnectButton` stub;
