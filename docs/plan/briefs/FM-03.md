# FM-03: Report client errors to Sentry and stop sending personal data

Fixes #1021 and #1022. This task is not sensitive; the issues are public.

## Objective

Client errors never reach Sentry (#1021):

- The whole client tree is wrapped in `ErrorBoundary`
  (`apps/app.mento.org/app/components/providers.tsx:36-47`). Its `componentDidCatch`
  only calls `logger.error` (`app/components/errors.tsx:22-28`), and `logger` only
  writes to the console (`packages/web3/src/utils/logger.ts`).
- In production, Next.js never reports errors caught by a boundary, so render crashes
  never reach Sentry.
- Handled money-path failures also go to the console only:
  - the tx-flow step catch (`packages/web3/src/features/tx-flow/engine.ts:133-152`);
  - swap `onError` (`features/swap/hooks/use-swap-transaction.tsx:174-186`);
  - the approve catch (`features/swap/hooks/use-approve-transaction.tsx:178-179`).

Sentry also receives personal data (#1022):

- `instrumentation-client.ts:32-42` records replays with all masking turned off and
  sets `sendDefaultPii: true`, which makes Sentry store the user's IP.
- `app/hooks/use-sentry-wallet-context.ts:23-36` sets the raw wallet address as the
  Sentry user and puts it in the `wallet` context.

This task does four things:

- makes the boundary report to Sentry;
- adds one small reporting seam (`reportError`) and wires it into the three handled
  paths above;
- turns replay masking back on and stops sending IPs;
- replaces the raw address with a pseudonymous id.

It does not change sample rates, `beforeSend`, `ignoreErrors`, `denyUrls`, the server
and edge configs, or any other `logger` call.

## Hard rules for this task

- **`reportError` never throws and never reports user rejections.** Telemetry must not
  break a flow.
- **Register the reporter in the app, importing from the `@repo/web3` root.** It must be
  the same module instance the engine and the swap hooks use. Do not add a new package
  entry point: `package.json` is frozen.
- **No wallet address or IP in any new `extra`, context or tag.**
- **Leave the rest of the Sentry config alone.** Keep `replaysSessionSampleRate`,
  `replaysOnErrorSampleRate` and `tracesSampleRate` unchanged. Change only the three call
  sites named here, not other `logger.error` calls.
- **`@repo/web3` tests run in node with no DOM.** App tests run in jsdom; use
  `@testing-library/react` (`render`, `renderHook`).

## Work

1. **`packages/web3/src/utils/error-reporter.ts` (new).**
   - `export type ErrorReporter = (error: unknown, context?: Record<string, unknown>) => void`.
   - `setErrorReporter(reporter: ErrorReporter | null)` stores the reporter in a module
     variable.
   - `reportError(error, context?)` does nothing when no reporter is set or
     `isUserRejectionForTelemetry(error)` is true. Otherwise it calls the reporter inside
     `try/catch`.
   - Add `export * from "./error-reporter";` to `utils/index.ts`.
2. **`error-reporter.test.ts` (new).** Cover:
   - no reporter → no-op;
   - the reporter receives the error and the context;
   - a `{ code: 4001 }` rejection is not reported;
   - a reporter that throws does not propagate.
3. **Call sites.**
   - `engine.ts`: after the user-rejection early return (`:134-141`) and before
     `onStepError`, add `reportError(error, { step: definition.id })`.
   - `use-swap-transaction.tsx:185`: add `reportError(error, { flow: "swap" })`.
   - `use-approve-transaction.tsx:179`: add `reportError(err, { flow: "approve" })`.
4. **`app/hooks/use-sentry-error-reporter.ts` (new).** `useSentryErrorReporter()`
   registers `(error, context) => Sentry.captureException(error, { extra: context })`
   with `setErrorReporter` in a `useEffect`, and resets it to `null` on cleanup. Call it
   in `WalletContextTracker` (`providers.tsx:26-29`), next to `useSentryWalletContext()`.
   Its test mocks `@sentry/nextjs` and `@repo/web3`, then checks both the registration
   and the reset on unmount.
5. **`errors.tsx`.** In `componentDidCatch`, keep `logger.error` and add:

   ```ts
   Sentry.captureException(error, {
     contexts: { react: { componentStack: errorInfo.componentStack ?? "" } },
   });
   ```

   `errors.test.tsx` (new) renders a throwing child inside `ErrorBoundary` and asserts
   that `captureException` receives that error plus a string `componentStack`, and that
   the fail screen shows. Mock `@sentry/nextjs`, `@repo/web3` and `@mento-protocol/ui`,
   and silence React's `console.error` in that test.

6. **`instrumentation-client.ts`.**
   - Set `sendDefaultPii: false` and fix its comment.
   - Use `Sentry.replayIntegration()` with its defaults, which mask all text, inputs and
     media. Delete the three `false` options and the "no sensitive data" comment.
7. **`use-sentry-wallet-context.ts`.**
   - Set the Sentry user to `{ id: sentryUserId(address) }` with no `username`, where
     `sentryUserId = (a: string) => keccak256(stringToHex(`mento-sentry:${a.toLowerCase()}`)).slice(2, 18)`
     (both functions come from `viem`). Export `sentryUserId` for the test.
   - Drop `address` from the `wallet` context. Keep the connector fields and the chain
     id.
   - The test (new) covers:
     - connected → the id is 16 hex characters and doesn't contain the address;
     - the context has no `address`;
     - the same address in different case gives the same id;
     - disconnected → `setUser(null)`.
